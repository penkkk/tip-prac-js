# Практическая работа № 1

Тема: подготовка окружения и первые программы на JavaScript.

## Автор и вариант

- Автор: Артём Петров.
- Группа: ЭФБО-01-25.
- Вариант: 1 (`totalTasks = 12`, `completedTasks = 5`, `dailyLimit = 3`).

## Окружение

- Операционная система: Linux 7.0.0-44-generic, x86_64.
- Bun: 1.4.2.
- Git: 2.53.0.
- Node.js и npm: в текущем окружении не установлены; для запуска используется совместимая среда Bun.
- Браузер: Chromium; версию нужно вписать после собственного запуска в браузере.

## Запуск

Команды выполняются из корня репозитория:

```bash
bun practice-01/js/hello.js
bun practice-01/js/types.js
bun practice-01/js/progress.js
bun practice-01/js/plan.js
bun practice-01/js/debug.js
```

Для запуска в браузере нужно открыть `practice-01/index.html`, указать нужный файл в атрибуте `src` элемента `script`, сохранить HTML, перезагрузить страницу и открыть Console в DevTools. Перед сдачей в `index.html` возвращено подключение `./js/hello.js`.

## Задание 1. Две среды выполнения

При запуске через Bun сообщения появляются в терминале, а `typeof document` возвращает `undefined`, потому что Bun не создаёт DOM страницы. В браузере вывод находится в Console, не в тексте страницы, а `typeof document` возвращает `object`.

## Задание 2. Типы и преобразования

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` | `"82"` | `string` | При наличии строки оператор `+` объединяет значения как текст. |
| `"8" - 2` | `6` | `6` | `number` | Оператор `-` преобразует числовую строку в число. |
| `Number("8") + 2` | `10` | `10` | `number` | `Number` явно преобразует строку, затем выполняется сложение. |
| `"12" > "3"` | `false` | `false` | `boolean` | Две строки сравниваются посимвольно: первый символ `1` меньше `3`. |
| `12 === "12"` | `false` | `false` | `boolean` | Строгое равенство не преобразует типы. |
| `Number("")` | `0` | `0` | `number` | Пустая строка при числовом преобразовании даёт ноль. |
| `Number("text")` | `NaN` | `NaN` | `number` | Текст нельзя преобразовать в число; `NaN` относится к типу `number`. |
| `Boolean("false")` | `true` | `true` | `boolean` | Любая непустая строка логически истинна. |
| `typeof null` | `"object"` | `"object"` | `string` | Это историческая особенность `typeof`; результат оператора — строка. |
| `typeof NaN` | `"number"` | `"number"` | `string` | `NaN` относится к числовому типу; результат `typeof` — строка. |

## Задание 5. Отладка

Исходная программа выводила `Выполнено: 32`, `Осталось: -24` и `Контрольная сумма: 6`.

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | Вместо суммы получалась строка `"32"`, затем неверный остаток | Оператор `+` объединял две строки | Обе строки преобразованы через `Number()` | Выполнено 5, осталось 3 |
| Граница цикла | Число 4 не участвовало в сумме | Условие `taskNumber < 4` завершало цикл слишком рано | Граница заменена на `taskNumber <= 4` | Контрольная сумма 10 |

Исправленный файл: [`js/debug.js`](./js/debug.js).

Перед сдачей необходимо самостоятельно выполнить пошаговую отладку и добавить `screenshots/debug-breakpoint.png`. Скриншот должен показывать строку остановки и значения переменных, а не только итоговую консоль.

## Вывод

В работе отработаны запуск JavaScript в разных средах, строгая проверка типов и диапазонов, условия, цикл `while`, явное преобразование строк и поиск логических ошибок через пошаговую отладку. Наиболее показательной оказалась ошибка сложения строк: программа не завершалась с исключением, но формировала неверный результат, поэтому одной проверки отсутствия ошибок выполнения недостаточно.
