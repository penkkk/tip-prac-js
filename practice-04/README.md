## Реализация

- `task-service.js` содержит чистые неизменяемые операции над задачами и новую функцию `updateTask`.
- `form-validation.js` преобразует строковый id формы в число, нормализует название, проверяет приоритет и режим редактирования.
- `task-storage.js` сохраняет конверт `{ version: 1, tasks }`, проверяет схему после чтения и безопасно обрабатывает ошибки хранилища.
- `task-view.js` строит карточки через `textContent` и не назначает обработчики отдельным карточкам.
- `main.js` управляет формой, делегированием событий, фильтром, редактированием, сохранением и сбросом.

Объект `storage` передаётся аргументом, поэтому модуль проверяется без глобального `window`. Данные после `JSON.parse` нельзя считать корректными автоматически: запись могла быть повреждена или создана другой версией приложения.

## Сохранение и восстановление

После добавления id 20 ключ `tip-js-practice-04:demo` содержит JSON с `version: 1` и пятью задачами. После перезагрузки показано сообщение о восстановлении из `localStorage`, а задача 20 остаётся в списке. Повреждённый JSON, неизвестная версия и неверная схема приводят к безопасному исходному набору с предупреждением. Сброс удаляет только ключ активного набора.

## Индивидуальный вариант

Вариант 1 содержит шесть задач подготовки учебного проекта с id `[11, 23, 37, 41, 58, 64]`. Общий и индивидуальный наборы используют ключи `tip-js-practice-04:demo` и `tip-js-practice-04:variant`, поэтому изменения не смешиваются.

## Вывод

Форма сочетает нативные ограничения HTML и прикладную проверку данных. Нативная проверка улучшает интерфейс, но правила уникальности и нормализации выполняются в JavaScript. После чтения хранилища применяется отдельная проверка схемы, потому что `localStorage` хранит только строки и не гарантирует корректность содержимого.
