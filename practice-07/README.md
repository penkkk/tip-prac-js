## Компоненты и состояние

`App` владеет `tasks`, `filters` и `editingId`. Видимая выборка и статистика вычисляются из актуального состояния на каждом рендере и не дублируются в отдельных состояниях. `TaskForm` хранит только черновик и ошибки полей; смена ключа формы сбрасывает черновик при переходе к другой записи. `TaskFilters`, `TaskList`, `TaskItem` и `TaskStats` получают данные через props, а действия передают родителю через обратные вызовы.

Все изменения массива неизменяемые: `map` заменяет запись, `filter` удаляет, spread добавляет. Стабильный `task.id` используется как React key. Название вставляется в JSX как текст, поэтому строка с HTML не исполняется.

## Индивидуальный вариант

## Ответы на контрольные вопросы

JSX описывает дерево элементов, а не HTML-строку. Props приходят от родителя и не изменяются дочерним компонентом; state принадлежит компоненту и обновляется через setter. Функциональная форма setter нужна, когда новое значение зависит от предыдущего. Управляемое поле получает `value` из state. `categoryId` из `select` преобразуется из строки в число. Производные значения не хранятся отдельно, чтобы не создавать рассинхронизацию. Подтверждение удаления выполняется до setter, поскольку updater должен оставаться чистым.
