## Цель и результат

Реализован Express API чтения задач и категорий. Сервер поддерживает строгую проверку id и query-параметров, совместные фильтры, поиск, HEAD, OPTIONS, CORS, 405 для известных ресурсов и структурированные ошибки 400/404/500. Данные хранятся в памяти отдельного экземпляра store.

## Установка и запуск

```bash
npm ci
npm start
```

API: http://127.0.0.1:5505/api. Другой порт: `npm start -- 5515`. Режим разработки: `npm run dev`.

## Реализация

`validation.js` разбирает положительные безопасные id и строгие фильтры. Строка `false` преобразуется явным сравнением, а не через `Boolean`. Разрешённые query проверяются до преобразования; повтор каждого имени отклоняется через `getAll`.

`task-service.js` фильтрует переданный массив без мутаций и ищет запись по id. `store.js` инкапсулирует копии исходных данных. `routes.js` связывает HTTP с store и формирует конверт ответа. `app.js` задаёт заголовки, ранний OPTIONS, Router, 404 и последний error middleware. `server.js` единственный открывает порт.

## Контракт

- `GET/HEAD /api/health` — состояние API.
- `GET/HEAD /api/categories` — три категории и `meta.total`.
- `GET/HEAD /api/tasks` — выборка и нормализованные `meta.filters`.
- `GET/HEAD /api/tasks/:id` — одна задача.
- `OPTIONS` — 204 и CORS; изменяющие методы — 405 с `Allow`.

`meta.total` равен размеру текущей выборки. ПР9 является read-only этапом; POST, PATCH и DELETE относятся к следующему расширению API.

## Исправленный дефект

Симптом: заготовка отвечала `NOT_IMPLEMENTED`. Причина: отсутствовали парсеры, предметная выборка и маршруты. Исправление: добавлены строгая нормализация, фильтрация, поиск, ответы ресурсов и 405. Повторная проверка: 38 модульных и 52 HTTP-теста прошли без ошибок.

## Ответы на контрольные вопросы

Query-строка не входит в путь маршрута и разбирается отдельно. `parseInt` нельзя использовать для id, потому что он принимает префикс `4abc`; нужна полная регулярная проверка и `Number.isSafeInteger`. 404 означает отсутствие ресурса, 400 — неверный ввод, 405 — известный ресурс с неподдерживаемым методом. Error middleware регистрируется последним, чтобы перехватывать ошибки маршрутов и не раскрывать stack. HEAD повторяет статус и заголовки GET без тела, OPTIONS сообщает правила CORS.
