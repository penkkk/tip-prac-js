## Цель и результат

React-интерфейс подключён к учебному HTTP API. Хук `useTaskData` загружает задачи и категории, сохраняет последний успешный снимок, различает ошибки чтения и изменения, отменяет устаревшие GET-запросы и повторно загружает данные после подтверждённой мутации. Данные живут в памяти процесса API и восстанавливаются после его перезапуска.

# во втором терминале

## Архитектура

`api-client` отвечает за URL, timeout, AbortSignal, JSON и классификацию HTTP/сетевых ошибок. `task-api` проверяет предметную схему ответов. `useTaskData` синхронизирует React с API. Компоненты отвечают за форму, фильтры и отображение.

Эффект загрузки зависит от стабильной ссылки `api`, четырёх полей фильтра и `revision`. Cleanup помечает запрос неактуальным и вызывает `abort`; обе ветви результата проверяют актуальность. `snapshot` не входит в зависимости, поскольку является результатом запроса.

Для мутаций используется отдельный `AbortController` и ref-блокировка, устанавливаемая до первого `await`. Поэтому два синхронных сохранения не создают два POST. Ошибка POST/PATCH/DELETE хранится в `mutationError`, а ошибка последующего GET — в `error`; успешная запись не объявляется неуспешной из-за сбоя обновления. При ошибке черновик формы сохраняется.

## Ответы на контрольные вопросы

Запрос выполняется в эффекте, потому что это синхронизация с внешней системой после рендера. Callback эффекта не является `async`, иначе он возвращал бы Promise вместо cleanup. AbortController экономит работу, а локальный флаг актуальности защищает даже от API, игнорирующего signal. State `pending` обновляется не мгновенно, поэтому для синхронной блокировки нужен ref. `true` от `saveTask` означает подтверждённую сервером запись, независимо от результата следующего GET. POST после тайм-аута автоматически не повторяется из-за риска дубликата.
