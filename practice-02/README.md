## 4. Модель данных и функции

Каждая задача содержит положительный безопасный целочисленный `id`, непустое название длиной до 100 символов, логический статус `completed` и приоритет `low`, `medium` или `high`. Название очищается от краевых пробелов, но внутренние пробелы сохраняются.

- [`src/data.js`](./src/data.js) хранит общий набор и данные варианта.
- [`src/task-service.js`](./src/task-service.js) содержит девять прикладных функций и не выполняет вывод.
- [`src/main.js`](./src/main.js) запускает общий и индивидуальный сценарии и отвечает за отображение.
- [`checks.js`](./checks.js) проверяет контракты функций, ошибки и отсутствие мутаций.

При успехе функции изменения возвращают `{ ok: true, tasks }`, а ожидаемые ошибки — `{ ok: false, error }`. `createTask` возвращает созданный объект в поле `task`. Функции чтения возвращают задачу, массив или числовую сводку напрямую.

`id` не равен индексу: индекс зависит от позиции записи и меняется после удаления, а идентификатор остаётся свойством конкретной задачи. `getTaskStats` возвращает число, потому что округление относится только к отображению и не должно терять точность расчёта. При обновлении создаются новый массив и новый объект выбранной задачи; неизменённые объекты разрешено использовать повторно.
